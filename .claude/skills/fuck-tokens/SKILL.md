# /fuck-tokens — автопилот по бэклогу

Аргумент: `$ARGUMENTS` — необязательно: число (максимум задач за прогон) и/или раздел
(`bugs` / `arch` / `tooling` / `ux`), как у `/backlog`. Пусто — без лимита, все открытые.

`/clear` модель вызвать не может, поэтому «чистый контекст» на каждую задачу — это
**отдельный субагент** (Agent tool, `subagent_type: "general-purpose"`): он стартует
с пустым окном, делает задачу и возвращает короткий итог. Основной сеанс только
оркестрирует — сам код не читает и не пишет, чтобы его контекст не разрастался.

**Файл состояния** `.claude/fuck-tokens.json` (в `.gitignore`) — задача(и), которые
сейчас в работе: `{"tasks": ["TASK-N"], "startedAt": "<ISO-время>"}`. Пишется перед
запуском субагента, удаляется только после проверки результата (шаг 3). Если он есть
на старте — предыдущий прогон оборвался посреди этих задач.

## 0. Предстартовая проверка и возобновление
Прочитать `.claude/fuck-tokens.json` и `git status --short`:
- **Файла нет, дерево чистое** → шаг 1.
- **Файла нет, дерево грязное** → остановиться: это чужие изменения, а `/task` в
  автономном режиме не сможет спросить, как с ними быть. Показать `git status`
  пользователю.
- **Файл есть** → прерванные задачи. Сообщить пользователю одной строкой
  «Возобновляю TASK-N, прерванную <startedAt>» и выполнить шаг 2 для них с
  **промптом возобновления** (ниже). Лимит из `$ARGUMENTS` их не считает.

## 1. Выбрать следующую задачу
Прочитать `.claude/skills/backlog/SKILL.md` и применить его разделы 1–2 (сбор состояния
и ранжирование: спринт → приоритет → оценка → зависимости) к `BACKLOG.md` с учётом
раздела из `$ARGUMENTS`. **`BACKLOG.md` при этом не править** (в т.ч. не ставить `✅`
задачам из git log — просто считать их сделанными), иначе дерево станет грязным.

Взять первую рекомендованную задачу. Если `/backlog` советует сделать её **одним
заходом** с другими (общие файлы, общий корень) — взять всю группу. Подтверждение
не спрашивать.

Пропускать задачи, уже помеченные в этом прогоне как «заблокирована». Открытых задач
не осталось или достигнут лимит → перейти к шагу 4.

## 2. Выполнить задачу в свежем субагенте
Записать `.claude/fuck-tokens.json` с номерами задач (если его ещё нет). Затем
запустить Agent (`general-purpose`, `description`: «TASK-N: <кратко>») с промптом:

> Ты работаешь в репозитории `C:\workSpace\tyulkin`. Прочитай
> `.claude/skills/task/SKILL.md` и выполни скилл `/task TASK-N [TASK-M …]` целиком
> (реализация, проверки, код-ревью через Skill tool, исправление замечаний, отметка
> `✅` в `BACKLOG.md`, коммит). Ты работаешь в автономном режиме, пользователя нет:
> - подтверждение плана для L-задач (шаг 0.4) не спрашивай — выбери самое разумное
>   решение и опиши выбор в отчёте;
> - если задача требует решения пользователя (продуктовый выбор без очевидного
>   варианта, контент, которого нет в репо — например, тексты резюме, ссылки,
>   PDF; внешние доступы) — ничего не коммить, откати свои правки
>   (`git checkout -- . && git clean -fd`, только если изменения твои) и верни
>   `STATUS: BLOCKED` с причиной и конкретным вопросом к пользователю;
> - не пушь; файл `.claude/fuck-tokens.json` не трогай.
> В конце верни ровно такой блок:
> ```
> STATUS: DONE | PARTIAL | BLOCKED | FAILED
> TASKS: TASK-N [TASK-M …]
> COMMIT: <хеш>
> CHECKS: <tsc / eslint / prettier / test / build — кратко, всё ли зелёное>
> REVIEW: <исправлено X / отклонено Y>
> NOTES: <1–3 строки: что сделано, что осталось (для PARTIAL) или почему не вышло;
>         проблемы вне задачи, замеченные по пути>
> ```

**Промпт возобновления** (для шага 0) — тот же, но первый абзац заменить на:

> Ты работаешь в репозитории `C:\workSpace\tyulkin`. Задачу(и) TASK-N уже начинали
> по скиллу `/task` (`.claude/skills/task/SKILL.md`, прочитай его), но работа
> оборвалась на середине. Определи по `git status`, `git diff` и
> `git log --oneline -10`, где остановились:
> - коммит с `TASK-N` уже есть, дерево чистое → задача завершена, просто верни
>   `STATUS: DONE` с хешем;
> - коммита нет → незакоммиченные правки — это частичная работа по задаче (реализация,
>   а возможно, и часть исправлений после ревью). Шаг 0.3 `/task` к ним не применяй —
>   это твои изменения. Сверь их с задачей в `BACKLOG.md`, доделай недостающее и
>   пройди шаги 2–7 `/task` (проверки, ревью, исправления, отметка, коммит).

Дождаться завершения субагента (уведомления о его окончании) — не запускать следующий
параллельно: задачи коммитят в одну ветку.

## 3. Проверить результат и решить, идти ли дальше
- `git status --short` и `git log --oneline -3`: дерево чистое (кроме игнорируемого
  файла состояния), коммит с номерами задач на месте.
- Записать итог (одна строка) в свой список.
- `DONE` или `PARTIAL` + чистое дерево → удалить `.claude/fuck-tokens.json`, вернуться
  к шагу 1 (частично сделанная задача с `_(частично: …)_` в бэклоге может снова
  попасть в выборку — второй раз подряд её не брать, пометить «заблокирована»).
- `BLOCKED` + чистое дерево → удалить `.claude/fuck-tokens.json`, пометить задачу
  заблокированной на этот прогон, вернуться к шагу 1.
- `FAILED`, грязное дерево, красные проверки или неожиданный формат ответа →
  **остановиться**, файл состояния **оставить** (следующий запуск `/fuck-tokens`
  попробует возобновить задачу), ничего не откатывать сверх того, что сделал
  субагент, и перейти к шагу 4.

## 4. Отчёт
Коротко, по-русски:
- таблица: задачи · статус · коммит · проверки · ревью;
- заблокированные задачи — с причиной и вопросом к пользователю;
- проблемы вне задач, которые нашли субагенты (их можно добавить через `/backlog add`);
- если остановились на ошибке — что сломалось, состояние дерева и что файл состояния
  оставлен: повторный `/fuck-tokens` возобновит задачу, а чтобы отказаться от неё —
  откатить правки и удалить `.claude/fuck-tokens.json`;
- прогресс: «Сделано N из M, текущий спринт: …».
Не пушить.
