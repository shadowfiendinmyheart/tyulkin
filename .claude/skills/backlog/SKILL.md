# /backlog — что делать дальше

Аргумент: `$ARGUMENTS` (необязательный).
- пусто — предложить 3 следующие задачи;
- число — предложить столько задач;
- `bugs` / `arch` / `tooling` / `ux` — только из соответствующего раздела;
- `add <описание>` — добавить новую задачу (см. последний раздел).

## 1. Собери состояние

1. Прочитай [BACKLOG.md](../../../BACKLOG.md).
2. Сделанные задачи — объединение:
   - отмеченных `✅ TASK-N` в таблицах;
   - упомянутых в истории: `git log --format=%s | grep -o 'TASK-[0-9]*' | sort -u`.
   Если задача есть в git log, но не отмечена `✅` в бэклоге — отметь её (это единственная правка, которую скилл делает без спроса), и упомяни это в ответе.
3. Частично сделанные — с пометкой `_(частично: …)_`; они идут первыми в своём приоритете.
4. `git status --short` — если в дереве есть незакоммиченная работа, связанная с какой-то задачей, скажи об этом: возможно, её стоит сначала довести.

## 2. Выбери кандидатов

Порядок ранжирования:
1. Текущий спринт из раздела «Рекомендуемый порядок» — первый спринт, в котором остались несделанные задачи.
2. Внутри — по приоритету P0 → P1 → P2 → P3.
3. При равном приоритете — сначала меньшая оценка (S < M < L): быстрые победы.
4. Учитывай зависимости, описанные в тексте задач. Например: TASK-33 (реестр команд) закрывает часть TASK-25/27/31 — если 33 близко, мелкие задачи из него лучше не брать отдельно; TASK-40 (тесты) желательно до крупных рефакторингов (33, 34); TASK-45 (CI) имеет смысл после 39 и 40.
5. Отметь задачи, которые логично делать **одним заходом** (одни и те же файлы, общий корень) — их можно передать в `/task` вместе.

Перед тем как рекомендовать задачу, бегло проверь по ссылке в бэклоге, что проблема всё ещё актуальна (код могли поменять в рамках другой задачи). Если уже неактуальна — отметь `✅` и скажи об этом.

## 3. Ответ

Формат — компактно, без пересказа всего бэклога:

```
Сделано: N из M (спринт 1: x/y). Текущий спринт: 1 — стабилизация.

1. TASK-23 · P1 · M — История команд записывает не то
   Почему сейчас: …одна строка…
2. TASK-25 · P1 · S — Парсер команд без границы слова
   Почему сейчас: …
3. …

Можно вместе: TASK-25 + TASK-27 (обе про команды/словари).
Запуск: /task TASK-23
```

Если спринт закрыт полностью — поздравь одной фразой и переходи к следующему.

## 4. `add <описание>` — новая задача

1. Возьми следующий свободный номер: максимум из `TASK-N` в BACKLOG.md и git log, плюс 1.
2. Определи раздел (Баги / Архитектура / Сборка / UX), приоритет и оценку по шкале из шапки бэклога. Найди в коде место и добавь ссылку в формате остальных строк.
3. Добавь строку в конец таблицы нужного раздела, не меняя остальное. Если задача явно относится к текущему спринту — допиши её номер в «Рекомендуемый порядок».
4. Покажи добавленную строку. Не коммить — это сделает `/task` вместе с работой.
