# /task — выполнить задачу из бэклога

Аргумент: `$ARGUMENTS` — номер задачи (`TASK-23`, `23`), несколько номеров через пробел/запятую, или свободное описание.

## 0. Подготовка

1. Прочитай [BACKLOG.md](../../../BACKLOG.md) и найди задачу(и) по номеру. Если аргумента нет — выбери следующую задачу по правилам скилла `backlog` и спроси подтверждение одной строкой, прежде чем начинать.
2. Если задача уже отмечена `✅` или её номер есть в `git log --oneline | grep TASK-N` — скажи об этом и остановись.
3. `git status --short` — запомни уже изменённые файлы. Это **чужие** изменения: не трогай их, не ревьюй и не коммить. Если они пересекаются с файлами задачи — спроси пользователя, как быть.
4. Если задача размера **L** или формулировка допускает несколько разумных решений — коротко опиши план (3–6 пунктов) и подтверди его перед реализацией. Для S/M — сразу делай.

## 1. Реализация

- Прочитай все файлы, на которые ссылается задача, и их соседей; пиши в стиле окружающего кода (React-хуки, SCSS-модули, словари в `src/localization/dictionaries/*.json` — менять **все** языки синхронно).
- Делай ровно то, что описано в задаче. Найденные по пути посторонние проблемы не чини — запиши их для итогового отчёта (их можно добавить в бэклог через `/backlog`).
- Если меняешь `*.module.scss` — обнови соответствующий `*.module.scss.d.ts` (`npx typed-scss-modules src`).

## 2. Проверки

Запусти и добейся чистого результата:

```bash
npx tsc --noEmit
npx eslint <изменённые .ts/.tsx>
npx prettier --check <изменённые файлы>   # не весь репо: см. TASK-39, пока он не закрыт
npm run build
```

Если в `package.json` появился настоящий `npm test` (TASK-40) — запусти и его. Если задача — баг из раздела «Как воспроизвести» в бэклоге, по возможности проверь сценарий вживую (скилл `run`).

## 3. Код-ревью

Вызови скилл `code-review` (уровень `medium`; для L-задач — `high`) на текущем диффе. Учитывай только находки в файлах этой задачи — изменения из шага 0.3 игнорируй.

## 4. Исправление замечаний

- Исправь каждую подтверждённую находку. Если считаешь находку ложной — не исправляй, но укажи её и причину в отчёте.
- После исправлений повтори шаг 2. Если исправления были существенными — повтори шаг 3 один раз; дальше не зацикливайся.

## 5. Отметка в бэклоге

В таблице [BACKLOG.md](../../../BACKLOG.md) замени ID выполненной задачи на `✅ TASK-N`. Строку не удаляй и остальной текст не меняй. Если задача выполнена частично — не ставь `✅`, а допиши в конец ячейки «Суть» `_(частично: что осталось)_`.

## 6. Коммит

- Добавляй файлы **поимённо** (`git add <file> …`), никогда `git add -A`/`.` — в дереве могут быть чужие изменения.
- Формат сообщения как в истории репо — префикс-тип, короткое описание на английском в нижнем регистре, номер задачи в конце:
  - `[fix] history records executed command TASK-23`
  - `[add] experience and skills commands TASK-48`
  - `[refactor] command registry TASK-33`
  - Несколько задач: `[fix] word boundary in parser TASK-25, english dictionary TASK-27`
- Коммить в текущую ветку. Не пушь.

## 7. Отчёт

Коротко (до ~10 строк): что сделано, какие замечания ревью исправлены/отклонены, результат проверок, хеш коммита, и замеченные по пути проблемы вне задачи, если есть.
